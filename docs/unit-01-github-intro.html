一句話定義

GitHub 是一個程式碼託管與協作平台——它託管你用 Git 管理的專案，並在此之上提供協作、追蹤、自動化與部署服務。 你可以把它想成「程式碼的雲端家園」。

Git · 本機工具
git init
git add .
git commit -m "first"
GitHub · 雲端平台
git push -u origin main
# 之後：Issues、PR、
# Pages、Actions…
關鍵區分：Git 是 Linus Torvalds 開發的版本控制工具（2005）， 跑在你的電腦上；GitHub 是網站平台（2008）， 讓你把 Git 專案託管上雲、多人協作。沒有 GitHub，Git 照樣能用；有了 GitHub，Git 才變成「團隊的工具」。

功能用途單元
Repo 託管程式碼雲端備份與版本歷史單元 2
Pull Request程式碼審查與合併流程單元 4
Issuesbug 與任務追蹤單元 5
GitHub Pages靜態網站免費部署單元 6
ActionsCI/CD 自動化單元 7
開源生態Fork、貢獻、社群單元 8

為什麼值得學

  • 業界標準：超過一億開發者使用，徵才時是作品集。
  • 完整工作流：從寫程式到上線，一站到底。
  • 免費：公開 repo 完全免費，私有 repo 也有免費額度。
  • 開源入口：參與全世界最大的程式碼社群。

帳號與認證 · Authentication

三種連線 GitHub 的方式：

方式說明
HTTPS + PAT用 Personal Access Token（個人存取權杖）當密碼，最常見
SSH key一對金鑰免密碼，安全且長久
gh CLI命令列登入，同時管理認證（單元 8）
安全：永遠不要在程式碼或 repo 裡提交密碼、Token、金鑰。 洩漏的 Token 要立即到 GitHub Settings 撤銷。詳細安全見單元 8。

認識 GitHub 的介面

進入任何 repo 頁面，先認得這幾個區塊：

Repo 頁面佈局 · LAYOUT
┌─────────────────────────────────────┐
│  owner/repo    ⭐ ★  | Code Issues PRs │
├─────────────────────────────────────┤
│  main ▼   add file ▼   commit 歷史   │
│  ├── README.md   ← 專案門面       │
│  ├── src/                            │
│  └── .github/                        │
└─────────────────────────────────────┘
標籤頁：Code / Issues / Pull requests /
        Actions / Projects / Wiki
看完這頁你應該能說出：
  • Git 與 GitHub 的關係與差別。
  • GitHub 的五大核心功能。
  • 三種認證方式與 Token 安全觀念。
  • repo 頁面的基本佈局。
